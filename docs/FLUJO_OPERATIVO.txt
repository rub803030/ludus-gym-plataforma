Si Vercel vuelve a poner Root Directory = apps/web, el deploy falla con

AVISO IMPORTANTE SOBRE VERCEL_TOKEN:
    El token actual fue obtenido de la sesion local de Vercel CLI y caduca a las
    8 horas. Mientras este vigente, el deploy automatico funciona. Cuando falle
    con "invalidToken", hay que crear un token permanente:
      1. Entrar en https://vercel.com/account/tokens con la cuenta rubnlira2@gmail.com.
      2. Crear un token con nombre "CI deploy ludus-gym-plataforma", scope del
         proyecto ludus-gym-plataforma y expiracion "No expiration".
      3. Copiar el valor (se muestra una sola vez) y guardarlo:
         gh secret set VERCEL_TOKEN --body "EL_TOKEN" --repo rub803030/ludus-gym-plataforma
      4. Volver a ejecutar:
         gh workflow run deploy-web.yaml --repo rub803030/ludus-gym-plataforma --ref master
    No se pudo crear ese token permanente desde la API porque la sesion CLI es
    OAuth y Vercel responde "Cannot create tokens for this app". Tampoco se pudo
    vincular el repo a Vercel por API: exige anadir primero una Login Connection
    de GitHub en la cuenta de Vercel.

6. ALTA DE GIMNASIOS (FLUJO EN DOS PASOS)
-----------------------------------------
Formulario publico: /register-gym (web, Android e iOS).
Campos obligatorios: nombre, direccion, ciudad, estado, CP, telefono, correo
de contacto, representante legal y RFC.
Opcionales: horario, sitio web/redes, descripcion y numero de sucursales.

1) POST /api/gyms/register (publico) crea el gimnasio en PENDING_VERIFICATION
   y envia al correo del dueno un enlace de un solo uso:
   /verify-gym?token=...  (deep link iOS: ludusgym://verify-email?token=...)
   Vigencia: 30 minutos (EMAIL_VERIFICATION_TTL_MINUTES).
2) Tras verificar el correo, se envia a los ADMIN un enlace de aprobacion:
   /approve-gym?token=...  tambien de un solo uso.
   Solo al abrirlo se activa el gimnasio, se generan codigo/QR y se notifica
   al contacto.
3) Consola global de aprobaciones: /admin/gyms (solo rol ADMIN).
   API: GET /api/admin/gyms/pending y POST /api/admin/gyms/:id/approve.

Errores exactos que debe mostrar la UI:
    CROSS_GYM_PASS      "Este pase pertenece a otro gimnasio"
    NO_GYM              "Unete a un gimnasio para continuar."
    EMAIL_NOT_VERIFIED  "Tu correo aun no esta verificado. Revisa tu bandeja."
    GYM_NOT_ACTIVE      "Este gimnasio todavia no esta activo."
    Sin conexion        "Sin conexion. Revisa tu red e intentarlo de nuevo."
Los tokens devToken/devLink solo se devuelven fuera de production.

Variables de la API en Fly relacionadas con correo:
    RESEND_API_KEY o SMTP_*, EMAIL_FROM, WEB_APP_URL,
    EMAIL_VERIFICATION_TTL_MINUTES=30, ADMIN_APPROVAL_EMAILS (opcional).
